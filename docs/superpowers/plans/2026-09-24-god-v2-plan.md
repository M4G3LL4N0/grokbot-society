# GOD v2 Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish a safe two-phase external-God handoff, benchmark the cost profile in dry mode, and publish a tiny operator handoff without any paid inference.

**Architecture:** Persist a bounded `GodJob` snapshot in each pending `events` payload, use the existing `ParticipantSelector` and actor-context compiler, and rehydrate the exact package across CLI processes. External live accounting is exposed only through `IntelligenceGateway`; dry mode persists validated usage without recording a provider call. Benchmarks run against fresh in-memory kernels and never mutate the operator database.

**Tech Stack:** TypeScript, Node 24+, built-in `node:sqlite`, pnpm, Vitest, existing Society services and gateway/budget/telemetry classes.

## Global Constraints

- Exactly one external God process; no new Person, Role, Actor, or GrokBot entities.
- `maxCallsPerEvent = 1`, `recursionDepth = 0`, `backgroundCalls = 0`, `maxRetries = 0`, and `maxSpeakers = 3`.
- Default operation remains zero-cost and deterministic; proactive and background paid inference remain disabled.
- Do not contact Grok, ChatGPT, or any network provider during implementation or verification.
- Use pnpm only; run Node 24+ for final verification.
- Do not add comments to source code.
- Do not commit unless explicitly requested.
